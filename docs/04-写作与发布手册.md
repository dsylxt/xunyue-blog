## 0. 五分钟上手

| 我想…… | 敲这条 |
| --- | --- |
| 新建一篇文章 | `npx hexo new post "文章标题"` |
| 本地看效果 | `npm run server` → 打开 <http://localhost:4000> |
| 改完没生效 | `npm run clean` 后重启 `npm run server` |
| 上传上线 | `git add . && git commit -m "更新" && git push` |
| 看线上 | <https://xunyue-blog.pages.dev/> |

> ⭐ 一句话：**写文章只管 `source/_posts/`，上线只管 `git push`**。
> 本站是「源码推 GitHub → Cloudflare Pages 自动构建」，不需要手动 `hexo deploy`。

## 1. 先认清这几个目录

| 路径 | 放什么 | 要不要动 |
| --- | --- | --- |
| `source/_posts/` | **所有文章**（`.md`） | ✅ 天天动 |
| `source/assets/` | 站内图片、头像、背景等静态资源 | ✅ 放图时动 |
| `source/<页面名>/index.md` | 独立页面（关于、画廊、友人帐……） | ✅ 加新页面时动 |
| `scaffolds/post.md` | 新建文章时的模板（Front-matter 骨架） | ⚠️ 想改默认字段时动 |
| `_config.yml` | 站点级配置（站名、域名、文章链接规则） | ⚠️ 少动 |
| `_config.fomalhaut.yml` | 主题配置（导航、封面、评论、侧栏……） | ⚠️ 少动 |
| `themes/fomalhaut/` | 主题源码（模板 / 样式 / 标签实现） | ❌ 尽量不动，升级会冲突 |
| `public/` | 构建产物，**不进 Git** | ❌ 不用管 |
| `docs/` | 就是这几份说明文档 | 可加 |

> 💡 `db.json`、`public/`、`node_modules/` 都写在 `.gitignore` 里，`git add .` 不会把它们传上去，放心。

## 2. 新建文章

### 2.1 用命令新建（推荐）

```bash
cd D:\Blog\my-blog
npx hexo new post "我的新文章"
```

生成：`source/_posts/2026-10-31-我的新文章.md`

- 文件名格式由 `_config.yml` 的 `new_post_name: :year-:month-:day-:title.md` 决定；
- 内容来自 `scaffolds/post.md`（已经带好 `mathjax: true`）；
- 标题里有空格、英文、符号都可以，文件名会原样保留。

也可以简写（默认 layout 就是 post）：

```bash
npx hexo new "我的新文章"
```

### 2.2 手动新建

不想用命令，就在 `source/_posts/` 里新建一个 `.md`，文件名照 `YYYY-MM-DD-标题.md` 起，开头补上 Front-matter 即可。

> ⚠️ 两个硬性要求：① 必须在 `source/_posts/` 里；② 开头必须有 `---` 包起来的 Front-matter，且 `title` 和 `date` 不能少。
> 少写 `date` 有时也能生成，但排序会乱，别省。

### 2.3 文件名 ≠ 网址（重要）

本站文章网址规则是 `permalink: posts/:abbrlink.html`，由 `hexo-abbrlink` 插件按内容算出一串哈希，例如：

```
https://xunyue-blog.pages.dev/posts/7a776471.html
```

含义：

- **改标题、改文件名，已发布文章的网址不会变**（链接不会失效）；
- 但**不要手动改或删 Front-matter 里的 `abbrlink`**，一改网址就变了，别人收藏的链接、搜索引擎收录、评论都会对不上；
- 新文章不写 `abbrlink` 会自动生成，不用管。

### 2.4 Front-matter 全字段

写在文件最开头，两个 `---` 之间，YAML 格式（**冒号后面必须有空格**）：

```yaml
---
title: 文章标题
date: 2026-10-31 11:00:00
updated: 2026-10-31 11:00:00
description: 一句话摘要，会显示在首页卡片上
keywords: 关键词1,关键词2
categories:
  - 代数学
tags:
  - 交换代数
  - 环论
cover: /assets/head.jpg
top_img: /assets/head.jpg
sticky: 1
toc: true
comments: true
mathjax: true
---
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `title` | ✅ | 文章标题 |
| `date` | ✅ | 发布时间，格式 `YYYY-MM-DD HH:mm:ss` |
| `updated` | 可选 | 更新时间；不写则按文件修改时间 |
| `description` | 可选 | 摘要，首页卡片和搜索结果都读它；不写则自动截取正文前 500 字 |
| `keywords` | 可选 | SEO 关键词，英文逗号分隔 |
| `categories` | 可选 | 分类，**列表写法，一行一个** |
| `tags` | 可选 | 标签，**列表写法，一行一个**（不要写成 `- 代数，环论`，那会变成一个标签） |
| `cover` | 可选 | 首页/归档卡片封面；不写就从 `cover.default_cover` 图片池里随机取 |
| `top_img` | 可选 | 文章页顶部大图；不写跟随 `default_top_img` |
| `randomcover` | 可选 | `true` = 每次刷新随机换封面 |
| `sticky` | 可选 | 置顶，数值越大越靠前（如 `sticky: 100`） |
| `toc` | 可选 | 是否显示右侧目录，默认跟随主题（`toc.post: true`） |
| `toc_number` | 可选 | 目录是否带序号 |
| `toc_expand` | 可选 | 目录默认是否展开 |
| `comments` | 可选 | 本文是否开评论，`false` 关闭 |
| `aside` | 可选 | 本文是否显示侧栏，`false` 隐藏（适合宽表格/长代码） |
| `highlight_shrink` | 可选 | `true` = 代码块默认折叠 |
| `copyright` | 可选 | 是否显示版权卡片（主题默认开） |
| `mathjax` | 可选 | 本文启用数学公式，**本站按需加载，写公式必须加** |
| `mermaid` | 可选 | 本文启用 Mermaid 图表 |
| `aplayer` | 可选 | 本文启用音乐播放器 |

> 💡 只写需要的字段，其余留空就是默认行为。
> 💡 已装 `hexo-blog-encrypt`，需要加密的文章可加 `password: 你的密码`（此功能本项目未实测，用前先在本地验证一次）。

### 2.5 可直接复制的模板


## 3. 常用 Markdown 语法

### 3.1 标题

```markdown
# 一级标题（文章内一般不用，标题已由 Front-matter 生成）
## 二级标题
### 三级标题
#### 四级标题
```

> ⚠️ `#` 和文字之间**必须有空格**。
> 💡 标题层级要连续，右侧目录（TOC）就是按 `##`/`###` 自动生成的。

### 3.2 文字样式

| 效果 | 写法 |
| --- | --- |
| **加粗** | `**加粗**` |
| *斜体* | `*斜体*` |
| ~~删除线~~ | `~~删除线~~` |
| ==高亮== | `==高亮==` |
| 下划线 | `++下划线++` |
| H~2~O 下标 | `H~2~O` |
| x^2^ 上标 | `x^2^` |
| `行内代码` | `` `行内代码` `` |

### 3.3 列表

```markdown
- 无序项
- 无序项
  - 缩进两个空格表示子项

1. 有序项
2. 有序项

- [ ] 待办事项
- [x] 已完成事项
```

### 3.4 引用、分割线、换行

```markdown
> 这是一段引用
> 可以写多行

---
```

- 分割线：单独一行写 `---`（**上面必须空一行**，否则会把上一行变成标题）；
- 换行：行尾加**两个空格**再回车，或直接空一行分段。**直接回车不会换行**。

### 3.5 链接与图片

```markdown
[Hexo 官方文档](https://hexo.io/zh-cn/docs/)
![图片描述](/assets/pic.jpg)
[![图片可点击](/assets/pic.jpg)](https://example.com)
```

- 站内链接写相对路径：`[关于我](/personal/about/)`；
- 外链会自动在新标签页打开（`external_link.enable: true`）；
- 图片路径详见[第 5 节](#5-图片上传与引用)。

### 3.6 代码

行内：`` `npm run server` ``

代码块（**一定要写语言名**，否则没有高亮）：

````markdown
```python
def gcd(a, b):
    while b:
        a, b = b, a % b
    return a
```
````

本站代码块主题是 `mac` 风格、带行号（`_config.yml` 的 `highlight` 段）。

### 3.7 表格

```markdown
| 左对齐 | 居中 | 右对齐 |
| :--- | :---: | ---: |
| A | B | C |
| 1 | 2 | 3 |
```

> 💡 表格前后都要空一行，否则不生效。

### 3.8 其他扩展语法

```markdown
脚注写法[^1]

[^1]: 这是脚注内容，会显示在文末。

术语
: 定义列表的写法（Pandoc 风格）

:smile: :rocket:     ← emoji 简码
```

### 3.9 转义

想显示 `*`、`_`、`#`、`{%` 这些符号本身，前面加反斜杠：

```markdown
\*不是斜体\*
\_不是斜体\_
\# 不是标题
```

> 💡 想**展示** `{% note %}` 这类标签语法而不让它生效，把它放进代码块（用四个反引号包住三个反引号的块）即可，标签只在正文里才会被解析。

## 4. 主题增强语法（外挂标签）

下面这些是 Butterfly / Fomalhaut 主题自带的标签，Hexo 构建时才会解析，**必须顶格写、成对出现**。

### 4.1 提示块 note

```markdown
{% note info flat %}普通提示{% endnote %}
{% note warning flat %}警告提示{% endnote %}
```

- 颜色：`default` / `primary` / `success` / `info` / `warning` / `danger`
- 形状：`flat` / `modern` / `simple` / `disabled`

> 效果：一个带图标的彩色提示框。写笔记时用来强调「定理条件」「易错点」很合适，比加粗更醒目。

### 4.2 标签页 tabs

```markdown
{% tabs 分组名 %}
<!-- tab 第一个标签 -->
内容一
<!-- endtab -->
<!-- tab 第二个标签 -->
内容二
<!-- endtab -->
{% endtabs %}
```

> 💡 `<!-- tab 标题@图标类名 -->` 可以带图标；`{% tabs 分组名, 1 %}` 的第二个参数是默认选中第几页（从 0 开始）。

### 4.3 折叠 hideToggle

```markdown
{% hideToggle 点开看答案 %}
被折叠的内容，适合放答案、长代码、剧透
{% endhideToggle %}
```

另有 `hideInline`（行内点击展开）和 `hideBlock`（整块隐藏）。

### 4.4 按钮与标签

```markdown
{% btn https://hexo.io/zh-cn/, Hexo 文档, icon-link, outline %}
{% label 绿色标签 green %}
```

- `btn` 参数用**英文逗号**分隔：`链接, 文字, 图标类名, 选项`；
- 选项可选：`color` / `outline` / `center` / `block` / `larger`；
- `label` 颜色：`default` / `blue` / `pink` / `red` / `purple` / `orange` / `green`。

### 4.5 时间线 timeline

```markdown
{% timeline 我的学习轨迹 %}
<!-- timeline 2026-09 -->
开始读 Atiyah《交换代数导引》
<!-- endtimeline -->
<!-- timeline 2026-10 -->
整理出一份小笔记
<!-- endtimeline %}
{% endtimeline %}
```

### 4.6 图表 mermaid

```markdown
{% mermaid %}
graph LR
  A[写 Markdown] --> B[hexo generate]
  B --> C[gulp 压缩]
  C --> D[git push]
{% endmermaid %}
```

> 💡 也可以在 Front-matter 写 `mermaid: true` 后用普通 ```mermaid 代码块，效果一样。

### 4.7 相册 gallery

```markdown
{% gallery %}
![](/assets/002.webp)
![](/assets/003.png)
{% endgallery %}

{% galleryGroup '校园' '随手拍' '/box/gallery/' /assets/002.webp %}
```

### 4.8 友人帐 flink

```markdown
{% flink %}
- class_name: 友情链接
  class_desc: 常看的博客
  link_list:
    - name: Hexo
      link: https://hexo.io/
      avatar: https://hexo.io/icon/favicon-32x32.png
      descr: 静态博客框架
{% endflink %}
```

### 4.9 数学公式

本站 `mathjax.per_page: false`（按需加载），所以**每篇要写公式的文章都要在 Front-matter 加 `mathjax: true`**。

```markdown
行内公式：设 $R$ 是 Noether 环

独立公式：
$$
\mathrm{Spec}(R) \longrightarrow \mathrm{Spec}(S)
$$
```

常用写法：

| 需求 | 写法 |
| --- | --- |
| 分数 | `\frac{a}{b}` |
| 根号 | `\sqrt{n}` |
| 求和 | `\sum_{i=1}^{n} a_i` |
| 矩阵 | `\begin{pmatrix} a & b \\ c & d \end{pmatrix}` |
| 花体 | `\mathcal{O}`、`\mathbb{Z}` |
| 中文公式内文字 | `\text{当且仅当}` |

> ⚠️ 下划线 `_` 在正文里会被当成斜体，公式外要写 `\_` 或放进反引号。

### 4.10 一个不存在的标签

主题**没有**注册 `{% span %}` 标签（虽然《外挂标签速查》里写了）。想居中/放大标题，直接用 HTML：

```html
<h2 style="text-align:center">居中的大标题</h2>
```

## 5. 图片：上传与引用

### 5.1 方式一：放 `source/assets/`（推荐，最省事）

1. 把图片复制到 `D:\Blog\my-blog\source\assets\`；
2. 正文里写 `/assets/文件名`：

```markdown
![交换代数笔记](/assets/shuoming.png)
```

- 路径以 `/` 开头表示**站点根目录**，跟文章在哪个文件夹无关，永远好用；
- 支持 jpg / png / webp / gif / svg；
- 建议文件名用**英文或拼音**，别用中文和空格（部分托管平台对中文路径处理不一致）。

### 5.2 方式二：用图床（外链）

图片传到图床（如 `https://beeimg.us.ci/...`），正文直接写完整链接：

```markdown
![](https://beeimg.us.ci/temp/xxxx.jpg)
```

优点是不占仓库体积、换电脑不丢图；缺点是图床挂了图就没了。**长期保存的图建议放 `source/assets/`。**

### 5.3 方式三：图片与文章同目录（默认关闭）

本站 `post_asset_folder: false`，所以 `![x](./pic.jpg)` **默认不生效**。
确实想用「每篇文章一个图片文件夹」，需要改 `_config.yml`：

```yaml
post_asset_folder: true
```

之后 `hexo new post` 会同时生成同名文件夹，把图片放进去，正文用 `![x](图片名.jpg)`。
> ⚠️ 改这个设置会影响所有文章的资源路径，已经用 `/assets/` 写好的文章不用改，但新文章要按新规则来。新手不建议动。

### 5.4 封面与顶部图

| 想要 | 怎么写 |
| --- | --- |
| 本文指定封面 | Front-matter `cover: /assets/xxx.jpg` |
| 本文不写封面 | 自动从 `_config.fomalhaut.yml` 的 `cover.default_cover` 随机取 |
| 每次刷新换封面 | `randomcover: true` |
| 文章页顶部大图 | `top_img: /assets/head.jpg` |
| 全站换封面池 | 改 `_config.fomalhaut.yml` 的 `cover.default_cover` |

> 💡 封面推荐 **1200×675（16:9）**，太小的图在卡片上会糊。

### 5.5 图片排版小技巧

```markdown
<!-- 控制宽度 -->
<img src="/assets/pic.jpg" width="60%">

<!-- 并排两张 -->
<img src="/assets/a.jpg" width="49%"> <img src="/assets/b.jpg" width="49%">

<!-- 行内小图标 -->
{% inlineImg /assets/icon.png 24px %}
```

## 6. 更新文章

### 6.1 改正文

直接编辑 `source/_posts/` 下对应的 `.md`，保存 → 浏览器刷新（`npm run server` 开着的话是热更新）。

> ⚠️ 只改正文**不要动 `abbrlink`**，否则网址会变。

### 6.2 标记「已更新」

想让读者看到更新时间，加一行：

```yaml
updated: 2026-10-31 15:00:00
```

不写也没关系，`_config.yml` 里 `updated_option: "mtime"`，会按文件修改时间显示。

### 6.3 改标题

改 Front-matter 的 `title` 即可，**网址不变**（网址由 `abbrlink` 决定）。
文件名要不要跟着改都行，文件名不参与网址生成。

### 6.4 删除文章

1. 删掉 `source/_posts/` 下对应的 `.md`（连带 `db.json` 缓存可不管）；
2. `npm run clean && npm run server` 确认列表里没了；
3. `git add -A && git commit -m "删除文章：xxx" && git push`。

> ⚠️ 删除后线上那篇文章的网址会 404，如果有外链引用，建议改成「已迁移」的说明页而不是直接删。

### 6.5 草稿

```bash
npx hexo new draft "还没想好的文章"     # 生成到 source/_drafts/
npm run server -- --drafts              # 本地预览时带上草稿
npx hexo publish "还没想好的文章"        # 定稿后转正，移到 _posts/
```

`_config.yml` 里 `render_drafts: false`，草稿**不会**被构建上线，可以放心写。

### 6.6 定时发布（本站不适用）

`_config.yml` 里 `future: true`，意思是「日期在未来的文章也会立刻生成」。所以**不能靠把 `date` 写到未来来做定时发布**，到点不会自动出现，反而现在就上线了。

真要定时，就用「草稿 + 到点手动 publish + push」。

### 6.7 置顶

```yaml
sticky: 100
```

数值越大越靠前。也可以只在正文里写一行 `<!-- sticky -->`。

### 6.8 分类与标签

- 不用提前创建，Front-matter 里写了就自动生成 `/categories/xxx/`、`/tags/xxx/`；
- 分类建议**少而稳**（一级分类），标签可以随意多；
- 首页的「分类磁贴」由 `_config.yml` 的 `magnet.display` 控制，**里面的 `name` 必须和文章分类名一字不差**，否则那一格点进去是空的。

```yaml
categories:
  - 代数学
tags:
  - 交换代数
  - 同调代数
```

## 8. 发布上线（把博客上传到线上）

### 8.1 原理

```
本地写 .md  →  git push 到 GitHub  →  Cloudflare Pages 自动构建  →  线上更新
                                     （npm run clean && npm run build && npx gulp）
```

- 仓库：`git@github.com:dsylxt/xunyue-blog.git`，分支 `main`；
- 线上地址：<https://xunyue-blog.pages.dev/>；
- **不需要** `hexo deploy` / `npm run deploy`（`_config.yml` 里那段 deploy 是主题模板的占位符，仓库地址是 `yourname/yourname.github.io`，跑了会失败）。

### 8.2 上传三步

```bash
cd D:\Blog\my-blog
git add .
git commit -m "新增：交换代数笔记"
git push
```

推送后等 1~2 分钟，Cloudflare 构建完成，刷新线上地址即可。

查看构建状态：GitHub 仓库页 → 最新提交右侧的绿勾/红叉；或 Cloudflare 后台 → Pages → 项目 → Deployments。

### 8.3 首次配置（换电脑时做一次）

```bash
# 1. 克隆（已有项目跳过）
git clone git@github.com:dsylxt/xunyue-blog.git
cd xunyue-blog

# 2. 装依赖（3~10 分钟）
npm install

# 3. Git 身份
git config --global user.name "你的名字"
git config --global user.email "你的邮箱@example.com"

# 4. 检查远程
git remote -v
```

> ⚠️ 用 SSH 地址（`git@github.com:...`）需要先配好 SSH Key；用 HTTPS 地址则要 Personal Access Token，GitHub 已不支持账号密码。
> ⚠️ `npm install` 前先换源：`npm config set registry https://registry.npmmirror.com`。

### 8.4 提交信息怎么写

不用太讲究，但建议能看出这次干了什么，出问题好回滚：

```bash
git commit -m "新增：交换代数笔记"
git commit -m "更新：修正公式笔误"
git commit -m "样式：调整首页卡片间距"
```

### 8.5 上线后验证

1. 打开 <https://xunyue-blog.pages.dev/>，`Ctrl + F5` 强刷（避免缓存）；
2. 点开新文章，确认网址是 `posts/xxxxxxxx.html`；
3. 确认图片能加载（本地能显示、线上不显示，多半是路径写成了本地绝对路径 `D:\...`）。

### 8.6 出问题怎么回滚

```bash
git log --oneline -5          # 找到上一次正常的提交
git revert <提交号>            # 生成一个反向提交（安全，推荐）
git push
```

> ⚠️ 不要用 `git reset --hard` 回滚已经 push 的提交，会改写历史，下次 push 会冲突。

### 8.7 换平台部署（可选）

| 平台 | 做法 | 构建命令 |
| --- | --- | --- |

## 10. 常见问题

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 新文章不出现在首页 | 文件不在 `source/_posts/`，或 Front-matter 格式错 | 检查目录与开头 `---`；`npm run clean` 重启 |
| 文章标题变成正文一部分 | `---` 只有两个，或 `---` 前有空行 | 用三个 `-`，且必须是文件第一行 |
| 报 `YAMLException` | 冒号后没空格，如 `title:我的文章` | 改成 `title: 我的文章` |
| 标签变成一个长串 | 写成了 `- 代数，环论` | 拆成两行，一行一个 |
| 公式显示成 `$...$` 原文 | 没加 `mathjax: true` | 加上后 `npm run clean` 重启 |
| 代码块没有高亮 | 反引号后没写语言名 | 写 ```` ```python ```` |
| 表格错乱 | 表格前后没空行 | 前后各空一行 |
| 图片本地能看线上不显示 | 用了 `D:\...` 或相对路径 | 改成 `/assets/xxx.jpg` |
| 改了样式不生效 | 浏览器缓存 / Hexo 缓存 | `Ctrl + F5`；再不行 `npm run clean` |
| 改了 `themes/` 下模板不生效 | Hexo 只在启动时读模板 | `Ctrl + C` 重启 `npm run server` |
| `git push` 被拒（rejected） | 远程有你本地没有的提交 | `git pull --rebase` 后再 push |
| push 后线上没变化 | 构建失败 / 还在构建 | 看 GitHub 提交状态和 Cloudflare Deployments 日志 |
| 线上样式全乱 | 构建漏了 gulp | 确认构建命令末尾有 `npx gulp` |
| `{% note %}` 原样显示出来了 | 标签写在了代码块外但拼写错，或没闭合 | 检查 `{% endnote %}`；想展示语法就放进代码块 |

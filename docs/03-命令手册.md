## 1. 打开终端

按 `Win + X` → 选「**终端**」或「**Windows PowerShell**」。
然后进入项目目录：

```bash
cd D:\Blog\my-blog
```

## 2. 环境检查（一次性）

| 命令 | 作用 | 预期输出 |
| --- | --- | --- |
| `node -v` | 检查 Node.js | `v22.22.2`（v18 以上都行） |
| `git --version` | 检查 Git | `git version 2.55.0.windows.3` |
| `hexo -v` | 检查 Hexo | 开头 `hexo-cli: 4.3.0` |
| `npm config get registry` | 看 npm 镜像源 | `https://registry.npmmirror.com/` |

**如果 Node / Git / Hexo 没装**（提示「不是内部或外部命令」）：
- Node：去 <https://nodejs.org> 下 LTS 版安装；
- Git：去 <https://git-scm.com/download/win> 安装；
- Hexo：`npm install -g hexo-cli`（**先做下面的换源**）。

**换 npm 镜像源（必做）**：旧淘宝源已废弃，不改会导致 `npm install` 大面积失败。
```bash
npm config set registry https://registry.npmmirror.com
```

**配置 Git 身份（必做）**：不配的话提交代码会报 `Please tell me who you are`。
```bash
git config --global user.name "你的名字"
git config --global user.email "你的邮箱@example.com"
```
> 邮箱建议用注册 GitHub 的那个，提交记录能关联到你的头像。
> 验证：`git config --global --list`，能看到 `user.name` 和 `user.email`。

## 3. 首次搭建（一次性）

```bash
# 1. 克隆主题仓库（"克隆即用"，不需要 hexo init）
git clone https://github.com/fomalhaut1998/hexo-theme-fomalhaut.git my-blog
cd my-blog

# 2. 安装依赖（最慢，3~10 分钟，耐心等）
npm install
```

> ✅ 成功标志：出现 `added xxx packages`，且目录下多了 `node_modules` 文件夹。
> ❌ 报大量 404 / ETIMEDOUT → 回到第 2 步确认镜像源换好了。
> 💡 用上面这条 `git clone` 的方式，`themes/fomalhaut` 里没有多余的 `.git`，不用额外处理。

## 4. 日常三条命令

### 4.1 本地预览 —— `npm run server`

```bash
npm run server
```
- 等价于 `npx hexo server`（或简写 `npx hexo s`）。
- 输出 `Hexo is running at http://localhost:4000/` 后**窗口会卡住不动**，这是正常的（它在持续运行）。
- 浏览器打开 <http://localhost:4000> 看效果。
- **停止**：在终端按 `Ctrl + C`。

> 💡 只要开着这个服务，改**文章 / 样式 / 脚本**后刷新浏览器就能看到（自动热更新），不用重启。

### 4.2 清缓存 —— `npm run clean`

```bash
npm run clean
```
- 等价于 `npx hexo clean`（简写 `npx hexo c`）。
- **什么时候用**：改了配置/模板没生效、页面样式乱了、构建结果诡异时，先清一次再重启。

### 4.3 生成静态文件 —— `npm run build`

```bash
npm run build
```
- 等价于 `npx hexo generate`（简写 `npx hexo g`）。
- 把博客生成到 `public/` 目录。
- **日常其实不用手动跑**（上线由云端自动构建，见第 6 节）。想本地看构建产物、或本地跑 gulp 压缩时才用。

### 4.4 新建文章 —— `npx hexo new post "标题"`

```bash
npx hexo new post "我的新文章"
```
- 在 `source/_posts/` 下生成 `2026-10-15-我的新文章.md`。
- 打开这个文件，在 `---` 分隔线下面写正文即可。

### 4.5 新建页面 —— `npx hexo new page "页面名"`

```bash
npx hexo new page "新页面"
```
- 生成 `source/新页面/index.md`，然后在 `_config.fomalhaut.yml` 的 `menu` 里加一行指向它。

## 5. Hexo 命令简写

Hexo 支持取首字母的简写，可以少打字（在项目目录里用）：

| 完整命令 | 简写 | 作用 |
| --- | --- | --- |
| `hexo server` | `hexo s` | 本地预览 |
| `hexo generate` | `hexo g` | 生成静态文件 |
| `hexo clean` | `hexo c` | 清缓存 |
| `hexo new post "标题"` | `hexo n "标题"` | 新建文章 |
| `hexo deploy` | `hexo d` | 部署（**本项目用不到**，见第 6 节） |

> ⚠️ 简写**必须在项目目录内**用；不在项目里执行只会打印用法帮助。

## 6. 部署上线（重点：走 `git push`）

### 6.1 本站的部署方式

> ⚠️ **本项目用不到 `hexo deploy` / `npm run deploy`。**
> 你的站点是 **Cloudflare Pages 连 GitHub 仓库自动构建**：你把源码 `git push` 上去，Cloudflare 自动帮你构建并上线。
> `_config.yml` 里的 `deploy:` 段是主题自带的备用方式，且它的仓库地址是占位符 `yourname/yourname.github.io.git`——**直接跑 `npm run deploy` 会推到不存在的仓库而失败**。

### 6.2 上线三步

```bash
git add .
git commit -m "更新博客"
git push
```

推送后等 1~2 分钟，刷新线上网址即可看到新内容。**全程不需要手动构建。**

### 6.3 Cloudflare 的构建配置（在 Cloudflare 后台填，不是命令）

| 配置项 | 值 |
| --- | --- |
| 生产分支 | `main` |
| 框架预设 | `None` |
| **构建命令** | `npm run clean && npm run build && npx gulp` |
| **输出目录** | `public` |
| 环境变量 | `NODE_VERSION` = `22` |

> ⚠️ 两个坑：① 构建命令**不能只写 `hexo generate`**（会报 `hexo: not found`），必须走 `npm run build`；② 必须加 `NODE_VERSION=22`，否则 Node 版本太旧。
> 💡 云端构建末尾带 **`npx gulp`**（压缩 html/css/js），所以本地 `npm run build` 出来的 `public/` 和线上**不完全一致**（本地少了 gulp 压缩），这是正常的。
> 想在本地完整复刻线上构建：`npm run clean && npm run build && npx gulp`。

### 6.4 首次推送（如果仓库还没建）

```bash
# 新建仓库后，把远程地址改成你的（你是 clone 下来的，origin 已存在，要用 set-url）
git remote set-url origin https://github.com/你的用户名/你的仓库名.git
git push -u origin main
```
> ⚠️ 首次推送会弹登录窗口，选浏览器授权；若提示要密码，用 **Personal Access Token**（GitHub 已不支持账号密码）。
> 验证远程地址：`git remote -v`。

## 7. 一键函数（进阶，可选）

在 `~/.profile` 末尾加上这几个函数（路径按自己情况改）：

```bash
BLOG_DIR="/d/Blog/my-blog"

bp() {                     # 一键发布
  ( cd "$BLOG_DIR" || exit 1
    git add -A
    git diff --cached --quiet && echo "无改动，直接推送" || git commit -m "${1:-更新博客}"
    git push )
}
bs() { ( cd "$BLOG_DIR" && hexo s ); }        # 本地预览
bn() { ( cd "$BLOG_DIR" && hexo n "$1" ); }   # 新建文章
```

执行 `source ~/.profile` 生效后，日常变成：

```bash
bn "我的新文章"     # 新建文章
bp                 # 提交 + 推送 → 云端自动上线
bs                 # 需要本地预览时再用
```

## 8. 改完东西要重启吗？

| 改了什么 | 怎么生效 |
| --- | --- |
| 文章 `.md`、`source/css`、`source/js` | 刷新浏览器（可能要 `Ctrl + F5` 强刷） |
| `source/js`、`source/css` 且 `inject` 里带 `?v=` | **必须把 `?v=` 改成新值**，否则吃旧缓存 |
| `_config.yml` / `_config.fomalhaut.yml` | **重启**：`Ctrl + C` 停掉再 `npm run server` |
| `themes/fomalhaut/` 下的 `.pug` 模板 | 重启 `npm run server` |
| 怎么都不生效 | `npm run clean` 清缓存后重启 |

> 💡 万能组合：`npm run clean && npm run server`。

## 9. 报错急救表

| 报错 / 现象 | 原因 | 解决办法 |
| --- | --- | --- |
| `'node' 不是内部或外部命令` | Node 未装或没进 PATH | 重装 Node.js LTS，重启终端 |
| `npm install` 大量 404 | npm 源是废弃的旧淘宝源 | `npm config set registry https://registry.npmmirror.com` |
| `Please tell me who you are` | Git 身份没配 | 执行第 2 步的 `git config --global ...` |
| `hexo: command not found` | Hexo 没装 | `npm install -g hexo-cli`（先换源） |
| `hexo server` 报找不到主题 | 主题名和配置不符 | 确认 `_config.yml` 的 `theme:` 是 `fomalhaut` |
| 改了 `themes/` 下文件不生效 | Hexo 只在启动时读模板 | `Ctrl+C` 停掉重启 `npm run server` |
| 敲 `hexo s` 只打印用法帮助 | **不在项目目录里** | 先 `cd D:\Blog\my-blog`，再执行 |
| 配置报 `YAMLException` | 冒号后漏了空格（如 `subtitle:''`） | YAML 要求 `键: 值` 冒号后**必须有空格**；用 `npx hexo version` 定位出错行 |
| `remote origin already exists` | clone 下来时 origin 已存在 | 用 `git remote set-url origin 地址`，不要用 `git remote add` |
| `git push` 要求输入密码 | GitHub 不支持密码推送 | 用 Personal Access Token 代替密码 |
| Cloudflare 构建报 `hexo: not found` | 构建命令写成了 `hexo generate` | 改成 `npm run clean && npm run build && npx gulp` |
| Cloudflare 构建报 Node 版本过低 | 没指定 Node 版本 | 加环境变量 `NODE_VERSION=22` |
| Cloudflare 构建后样式全乱 | 漏跑 gulp 压缩 | 确认构建命令末尾有 `npx gulp` |
| 页面能打开但图片挂了 | 主题默认走公共 CDN | 属正常现象，可后续换自己的图床 |

## 附：命令与两个配置文件的关系（速记）

| 命令 | 读哪个配置 |
| --- | --- |
| `npm run server` | 读 `_config.yml` + `_config.fomalhaut.yml`（启动时读一次） |
